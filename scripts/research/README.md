# Ubuntu investigation utilities

Temporary, manually run research tools for Ubuntu 26.04 LTS, added November 6,
2026. These are separate from the HIDS application: no collector, detector,
capability manager, normalized contract or dashboard is implemented here. This
research-tooling task supersedes the earlier documentation-only task restriction
in [AGENTS.md](../../AGENTS.md) for these utilities only. It does not authorize
production implementation or host configuration changes.

## Transfer and execution

The repository's `scripts/research/` is the canonical source. Make corrections
there first, then synchronize the research sources and README, preserving `common/`.
Keep compiled binaries and raw reports out of the canonical/shared source directory.
The established UTM VirtFS share is `CCDC-Transfer/research/` on macOS and is
mounted at `/mnt/ccdc-transfer/research/` in Ubuntu. Locate the macOS share rather
than assuming its absolute path; do not overwrite unrelated transfer contents.

In the VM, use an ordinary account, not a root shell:

```sh
cd /mnt/ccdc-transfer/research
bash system-inventory.sh
bash process-research.sh
# Optional selected read-only privileged comparisons:
bash system-inventory.sh --privileged
bash process-research.sh --privileged
```

If the share is unavailable, copying the complete directory over an already
available SSH connection is an alternative (replace the destination):

```sh
scp -r scripts/research vm-user@vm-host:~/hids-research
```

Reports still go to the VM's private temporary directories, not the shared folder.
Transfer only reviewed report copies through the share separately.

`--help` prints usage without collecting. Do not run `sudo bash ...`: root launches
are refused so ordinary-user observations retain their meaning. Bash, coreutils
(including `timeout`), grep, and ordinary Ubuntu base tools are expected. Missing
optional tools are reported; nothing is installed. Linux is required, but the
scripts do not claim another Linux release is a validated target.

A report path is printed before collection. Each invocation creates a fresh
`hids-research.XXXXXXXX` directory under `${TMPDIR:-/tmp}` with mode 0700, and a
UTC-named report such as `process-research-2026-11-06-143000.txt` with mode 0600.
No existing report is overwritten. Choose a trusted local TMPDIR if needed;
temporary storage may be cleared on reboot. Move reports into your own private
research storage if retaining them. No repository report files are generated by
default. File creation uses restrictive umask, not changes to existing permissions.

## Checks and privilege boundaries

| Check | Ordinary-user behavior | With `--privileged` |
|---|---|---|
| OS/kernel, systemd and package versions | Reads release metadata, versions; excludes hostname/machine ID | Same |
| Audit | `auditctl -s`, `auditctl -l`, service properties | Repeats status/rules via sudo |
| Baseline execution records (before controlled child creation) | `ausearch -m EXECVE -x /usr/bin/sleep -ts recent --raw` | Repeats the same query via sudo |
| Journal inventory | Service properties and storage usage | Repeats storage usage via sudo |
| Controlled Audit search (after child creation) | `ausearch -p "$TEST_PID" -m EXECVE -ts recent --raw` | Repeats query via sudo; positive numeric PID must match the controlled child |
| Controlled journal search | Current boot, child PID AND resolved sleep executable, bounded to experiment interval, last 30 records | Same ordinary-user view |
| `/proc` | Own observer status or controlled same-user child only | Never elevated |
| Kernel config and tracepoint metadata | Selected config entries and existing tracefs paths only | Never elevated; inaccessible metadata remains unresolved |
| bpftool | Presence and version only | No feature probe, program listing or loading |

Sudo is requested lazily only for the allowlisted reads in the table. `sudo -v`
requests authorization on the original terminal; it can use existing cached
credentials. Subsequent reads use `sudo -n` and are bounded. Denied authorization
is recorded without aborting remaining ordinary checks. Credentials are never
invalidated; sudo configuration is untouched. No whole script or shell is elevated.
Sudo itself may refresh its normal credential cache and generate authentication
logs, so privileged and ordinary runs are separate experimental contexts.

The research tools do not modify journald, PAM, auditd, Audit rules, tracing state, BPF,
kernel parameters, services, permissions or firewall configuration. They do not
install dependencies, subscribe to the Audit kernel stream, attach tracing
programs or run `bpftool feature probe`. The Bash scripts do not open a process
connector subscription; the separate, explicitly invoked C++ experiment below
opens one. Bash scripts create only their private reports and, in the process
script, one temporary `/usr/bin/sleep 3600` child. Ordinary command execution may
itself generate logs.

## What the experiments establish

`system-inventory.sh` records the environment, journal/audit tooling and service
state, active Audit rules/status, proc mount options and own-process access,
selected running-kernel config options, existing tracefs metadata and tool presence.
Journal access checks inspect accessible storage usage without dumping messages.
This is partial access evidence, not proof of access to every journal namespace.
The systemd package/client version provides journald build context; the script
does not independently attest the running journald binary's version.

`process-research.sh` additionally samples recent existing Audit EXECVE events for
the literal `/usr/bin/sleep` path as a **pre-experiment baseline**. This filter may
miss records using a resolved executable path. It does not establish that the
controlled child was recorded. `ausearch recent` normally means the last ten minutes.
The query preserves associated records within each matching Audit event, but
report caps can truncate an event. Previous sleep invocations may match, so this
sample is not attributed automatically to the new child. No audit rule means
execution records may not be emitted; missing tools/access and empty results are
separate possibilities. `ausearch` can return nonzero for no matches as well as
errors; inspect its diagnostic rather than interpreting every nonzero as failure
of Audit. No execution-wide history is collected.

After creating the controlled child and taking its snapshots, the script queries
Audit by that child's PID using `ausearch -p "$TEST_PID" -m EXECVE -ts recent --raw`,
first as the ordinary user and then optionally through sudo. The privilege
allowlist checks exact argument count, positions, a positive numeric PID and
identity with the script's controlled PID; it accepts no extra options, joined
command strings or arbitrary shell execution. PID reuse within the recent window
and delayed writes remain attribution limits. Review event times and associated
records; a PID match alone is not a finalized correlation identity. There is no
retry/backfill guarantee, and an empty query is not proof of absent recording.

The controlled child supplies PID/PPID, name, executable, arguments, state,
UID/GID real/effective/saved/filesystem columns, supplementary groups, threads,
raw proc stat start ticks, clock frequency, boot epoch and a ps start-time view.
The script resolves `/usr/bin/sleep` with `readlink -f` before spawning it, then
polls the resolved `/proc/PID/exe` path up to 20 times with 0.05-second pauses.
This supports the VM's observed `/usr/lib/cargo/bin/coreutils/sleep` target without
hardcoding it. The report explicitly states whether the expected executable was
observed. Poll exhaustion means exec is **not confirmed**, not that it failed;
access, scheduling and process exit can affect observation. If resolution fails,
confirmation is not investigated and the executable-filtered journal query is
skipped. Other child snapshots and the PID-scoped Audit query still run, with
exec confirmation unresolved. These are non-atomic observations of
one same-user process, not a test of other-user or future collector identities.
Raw `/proc/PID/stat` field 22 is start ticks since boot; do not parse the parenthesized
command name by naive whitespace splitting. It is context, not execution history.

Only child journal messages in the experiment interval are queried, with selected
JSON fields, the current boot, child PID and `_EXE` equal to the resolved executable
path. The last-30-record limit and shared per-check output limits remain in place.
If polling did not confirm exec but resolution succeeded, the query still uses
the expected path and is not itself treated as exec confirmation. A journal entry's emitter metadata is not a generic exec event; an
empty sample is not evidence that execution did not happen. Writes may arrive
after the interval and be missed. There is no privileged journal-message retry,
historical backfill, multi-source correlation or attempt counting. The earlier
[SSH research](../../docs/research/authentication.md#7a-ssh-journald-follow-up)
shows why emitter names and overlapping queries must be understood first.

Kernel config `y`/`m` is build evidence, not proof of usable runtime support. An
explicit `# CONFIG_X is not set` is scoped evidence of disabled build support;
an absent entry or unreadable config is Unknown. Existing exec/fork/exit tracepoint
metadata is inspected at standard tracefs and legacy debugfs locations. Failed
reads may reflect unmounted filesystems or inaccessible parents; they never prove
a tracepoint does not exist. Connector delivery, BPF runtime usability, tracing,
event loss, reboot continuity and historical completeness are **not investigated**.

## Reports, failures and privacy

Reports contain purpose, UTC collection/check times, observer numeric IDs,
commands, bounded observations, exit statuses, missing-tool messages and limitations.
There is no numerical confidence or security-coverage score. Use the scoped states
in [field discovery](../../docs/research/field-discovery.md#6-field-availability-classifications)
when reviewing: unsupported requires evidence, unavailable is not inaccessible,
and not investigated is not not emitted. These scripts leave ambiguous failures
Unknown instead of deriving a capability verdict from an exit code.

Each probe has a 10-second timeout (plus two seconds before forced termination),
and output is capped at 32768 bytes / 200 lines, with control characters rendered
visibly. Sudo authorization itself is interactive and not timed out. Exit 124/137
may indicate timeout; 141 may mean output limiting. Caps are declared for every
report and can split records; reports are not complete parser fixtures. A successful
script exit means the report sequence finished, not that all probes succeeded.
Initialization failures abort; individual missing commands and failed probes do not.

EXIT, INT, TERM and HUP cleanup terminates only the still-running child job PID
created by the process script and waits for it; it never uses `pkill`, `killall`
or process-group termination. SIGKILL, host crashes and power loss cannot be
trapped; the child's one-hour lifetime bounds this residual case. The child is
normally stopped immediately after the snapshot and journal query.

Do not share reports unreviewed. Audit rules/events can contain paths, keys,
user/account IDs, command arguments and identifying source metadata; diagnostics
can also disclose local paths. Kernel/mount details can fingerprint a host.
No environment values, unrelated process argument enumeration, credentials or
whole journal histories are requested. Review a separate redacted copy, replace
identifiers consistently so joins remain understandable, record redactions, and
share via a trusted private channel. Never commit raw reports. Root can read the
files; these permissions do not protect against compromised root.

## Separate C++ process connector experiment

[process-connector-test.cpp](process-connector-test.cpp) is a manually invoked,
temporary cn_proc experiment, **not production collection**. It is not called by
either Bash script. It subscribes once to process connector notifications, which
is a transient socket operation rather than a persistent configuration change.
Unlike the Bash inventory, it actively tests this single notification interface.

The owner reports Ubuntu kernel `7.0.0-42-generic`, built October 15, 2026. A
[November 2 socket-cleanup patch proposal](https://lkml.iu.edu/hypermail/linux/kernel/2611.0/02751.html)
and [November 3 automated review](https://lkml.iu.edu/hypermail/linux/kernel/2611.0/06934.html)
raise cleanup and concurrent-control concerns. Neither establishes which fixes
are installed in the VM. This experiment uses one socket, one LISTEN, one child
and one IGNORE attempt, in one thread. Do not loop it, stress-test it, share its
socket with other controllers or run several instances concurrently.

### Build and run once, as an ordinary user

Use only an already installed Ubuntu C++ compiler and Linux UAPI headers; if
`command -v c++` fails, stop. Do not install dependencies or use sudo. Compiling
on the VM uses its native architecture, including ARM64. Compile into a fresh
private VM directory, so the VirtFS source mount need not permit execution:

```sh
cd /mnt/ccdc-transfer/research
command -v c++
# Continue only if the existing compiler is available:
umask 077
work_dir=$(mktemp -d /tmp/hids-cnproc.XXXXXXXX)
if c++ -std=c++20 -O2 -Wall -Wextra -Wpedantic \
    process-connector-test.cpp -o "$work_dir/process-connector-test"; then
    report="$work_dir/process-connector-$(date -u '+%Y-%m-%d-%H%M%S').txt"
    "$work_dir/process-connector-test" > "$report"
    result=$?
    printf 'Experiment exit status: %s; report: %s\n' "$result" "$report"
    cat "$report"
fi
```

An unavailable compiler, missing/outdated `linux/cn_proc.h` (including
`proc_input`), unexpected ABI assertions or a non-executable temporary mount
means stop and report the limitation. There is no fallback to an unfiltered
legacy subscription. The program refuses UID/EUID 0 and never invokes sudo.
Do not automatically retry permission failures as root. Reports remain local
and private; transfer only a reviewed copy through the shared folder.

### Subscription, evidence and cleanup

The program creates `NETLINK_CONNECTOR`, joins the `CN_IDX_PROC` multicast group,
and sends the extended `proc_input` request with exactly FORK, EXEC and EXIT bits.
Control packets are zero-initialized, sized from installed UAPI structures and
serialized with `memcpy`, without embedding flexible arrays or assuming wire
alignment. Static assertions check sizes/offsets, including the 8-byte aligned
monotonic timestamp. It never transmits malformed controls or probes other masks.

The inspected [upstream v7.0 cn_proc implementation](https://github.com/torvalds/linux/blob/v7.0/drivers/connector/cn_proc.c)
sends ACKs as `PROC_EVENT_NONE`; its filter can suppress ACKs for a restricted
mask. Its send path replaces ACK sequence/CPU with per-CPU values. The experiment
waits at most one second, matches kernel-sourced ACKs by connector ID and a
request-specific ACK cookie, and reports explicit connector/netlink errors with
numeric errno. A generic netlink success is not a connector subscription ACK.
An ACK timeout is **inconclusive**, not confirmed success or permission denial;
without retrying LISTEN, the program proceeds to one controlled delivery check.
Explicit failure stops before creating the child. An owner-reported Ubuntu run now observed all three child notifications without
a LISTEN ACK; see the [research record](../../docs/research/process-connector.md).
Upstream source is not verification of the installed binary.

One direct child is created with `fork()` and `exec`s `/usr/bin/sleep 2`. Only its
exact PID/TGID FORK/EXEC/EXIT notifications are displayed, including parent IDs
where the event provides them, CPU, connector sequence and `timestamp_ns`.
Kernel PID is the thread ID; TGID is the process ID. The single-thread child makes
them equal. Parent fields in EXIT can be zero if unavailable; those are native
values, not invented identities. No process arguments, usernames, unrelated event
payloads or full system activity are printed. Unrelated notifications necessarily
arrive at the socket and are discarded after internal sequence accounting.
No records are persisted by the program itself; stdout redirection above is opt-in.

The timestamp is kernel monotonic nanoseconds (`ktime_get_ns()` upstream), **not
wall-clock time**. Sequence tracking is separate per CPU (up to CPU ID 4095),
handles unsigned wraparound and reports discontinuities without calling them a
loss count. Filtering, ACKs, reordering and drops can create gaps. CPU IDs beyond
the tracking bound are counted as untracked; their relevant child events can
still be displayed. Reception is limited to five seconds after fork, at most
10,000 datagrams per receive phase and eight displayed child events. It stops
earlier if all three child event types are observed. Empty/missing results do
not prove unsupported functionality or complete access.

Receive handling validates kernel sender identity, netlink/connector lengths,
expected event size and multi-message framing. It decodes into aligned objects
using `memcpy`, including when the on-wire event is only four-byte aligned.
Unexpected/malformed records are counted and skipped safely; `NLMSG_OVERRUN`,
`ENOBUFS`, `MSG_TRUNC` and `MSG_CTRUNC` are disclosed as incomplete evidence.
No automatic recovery, backfill or resubscription occurs. Initial namespaces,
access policy, installed kernel behavior and busy-host loss can affect results.

Cleanup sends one explicit IGNORE after any LISTEN attempt, including a failed or
interrupted send whose effect is uncertain, then terminates/reaps only its owned
child and closes the socket. A failed bind or pre-LISTEN error has no subscription
to cancel. The child closes its inherited socket reference before exec and never
sends controls; the parent's reference remains open. The unreaped child's PID is
reserved until cleanup, preventing a kill of a reused PID. A still-running owned
child is killed for deterministic cleanup; ordinary completion reports its exit
status. SIGINT, SIGTERM and SIGHUP handlers only set a flag; the main thread then
performs serialized cleanup. Error returns also run the same cleanup through RAII.
SIGPIPE is ignored so a closed report pipe cannot bypass cleanup.

The program does **not wait for an IGNORE ACK**: upstream `cn_proc_ack()` returns
without sending when listener count falls below one, and the filter can suppress
it too. A successful IGNORE send is reported as sent, not verified kernel
completion. If unsubscribe fails, the report marks cleanup inconclusive; do not
rerun automatically. SIGKILL, a crash or power loss cannot guarantee IGNORE, and
explicit unsubscribe does not resolve the upstream kernel defects. This is a
bounded evidence-gathering experiment, not a proof of kernel safety or suitability
for production monitoring. Exit 0 means all three child event types were seen
without recorded receive/cleanup failures, not historical completeness. Nonzero
means inspect the report; permission errors and inconclusive observations differ.

## Extending and validation

Future authentication, filesystem, service, privilege-change and network scripts
can source `common/utilities.sh`, call `init_report`, `section`, `record`, then
`finish_report`. Add a specific documented read-only privilege allowlist entry
only if justified; never pass untrusted command strings to a shell. Keep samples
narrow and add dedicated cleanup for owned temporary resources. No additional
research scripts are implemented now. Follow the
[schema research process](../../docs/schema-design-process.md); report contents
are native evidence, not changes to the ECS contract.

Local validation on macOS: Bash syntax checks, simulated report initialization,
missing/failing-command continuation, mode checks, and isolated cleanup tests.
Focused correction validation on macOS also covers resolved-path success/failure,
exec confirmation/poll exhaustion, exact PID Audit arguments, journal filter
restrictions, privilege allowlist rejection and child cleanup using local test
doubles. The owner reported Ubuntu's resolved sleep path; these corrected probes
have **not been run or validated on Ubuntu**. Run both ordinary
and privileged versions on the VM, inspect reports and cleanup, and retain
sanitized representative records before deriving mappings or production decisions.

Source references for query semantics:
[systemd journalctl manual](https://www.freedesktop.org/software/systemd/man/latest/journalctl.html)
(AND filters, output limits and access scope) and the
[ausearch manual](https://man7.org/linux/man-pages/man8/ausearch.8.html)
(event grouping and query options). These references do not establish behavior
on our VM; retain installed command versions and diagnostics in each report.
